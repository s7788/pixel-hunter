# pixel-hunter 開發說明

給要改這個 mod 的人：設計範圍、素材管線與已知限制。使用者介紹在 [README.md](../README.md)（中文版 [README.zh-TW.md](../README.zh-TW.md)）。

獵人（大劍、太刀或弓）跟著 Claude 的主回合出營、狩獵九隻魔物之一、撤退。魔物註冊、九隻魔物、討伐統計與 CLI 終端機畫面來自另一條開發線（v0.4–v0.9.5），v0.10 與武器線合併。美術方向來自 `hunt_8bit_reference`（v1.2）參考包，以像素改編為準，不是原作素材。

## 目前範圍

- 動作 25 組：C01／C03／C08／C15／C17、G03／G05／G06、L01／L02／L03／L05／L06、B01／B04／B05／B06／B07、V01／V02／V14／V17／V23／V25／V26（營地另有 C02／C21）。
- 場景：S03 營地；每隻魔物有自己的狩獵場（冰呪龍在 S02／S04 輪替），一場中途不換景。S05 結晶廢墟由 `tools/make_s05.py` 畫出。
- 魔物註冊（v0.4）：魔物是 `hooks/monsters/` 下的資料定義（招式、數值、專屬機制），引擎不再寫死冰呪龍。新狩獵依種子從已啟用的魔物抽一隻，一場中途不換種。已啟用：冰呪龍（S02／S04，5 分鐘）、大凶豺龍（S01 森林，2 分鐘）、飛雷龍（S01 森林，3 分鐘）、蠻顎龍（S01 森林，4 分鐘）、冰牙龍（S02 雪原，5 分鐘）、迅龍（S01，5 分鐘）、轟龍（S02，5 分鐘）、雷狼龍（S01，6 分鐘）、殲世滅盡龍（S05 結晶廢墟，7 分鐘）。
- 大凶豺龍（v0.4，依 `pixel-hunter-monster-expansion-spec-v1.0` 4.1）：前咬、腹部重壓、側身翻壓、吐出胃液團；戰鬥 20 秒後膨腹 20 秒（較慢、只用重壓與翻壓），腹部打破即消腹並倒地 24 tick。胃液團是獨立特效，飛行中才有攻擊框。
- 飛雷龍（v0.5，規格 4.2）：前咬、躍身撲擊（跳起 28px、前撲 80px，框跟著根部高度）、迴身尾掃（前後兩側）、帶電尾砸；戰鬥 12 秒後蓄電 12 tick，蓄電中受傷達最大 HP 5% 即中斷；完成後帶電 16 秒才會出帶電尾砸，時間到或受傷達 15% 放電收招。只有直接傷害，沒有麻痺。
- 蠻顎龍（v0.6，規格 4.3）：俯身咬擊、低頭衝撞（前移 120px，停在獵人身前）、回身尾掃、火焰吐息；戰鬥 20 秒後抬鼻冠、展背帆 12 tick，期間受傷達最大 HP 5% 即中斷；完成後火焰準備 18 秒才會吐火（近／中距，準備期間不主動走近），每次吐息後冷卻 12 tick。火焰只向前、畫在攻擊框上，只有直接傷害、沒有灼燒。
- P2／P3（v0.7，規格 4.4–4.9）：冰牙龍（翼部破壞、落地失衡、固定冰旋風）、迅龍（怒後二連尾砸、尾卡地空檔、三連尾棘）、轟龍（折返衝刺、怒時三段、三次後疲勞）、雷狼龍（蓄電量、超帶電與雷電爆發、三連拍）、殲世滅盡龍（白／黑棘、破棘倒地或硬直、鎖定落點的俯衝）。迅龍與轟龍共用怒氣規則。S05 結晶廢墟由 `tools/make_s05.py` 畫出（參考包沒有這張圖）。
- 討伐統計（v0.8）：pane 下方一列「討伐 N」＋各魔物頭像與隻數（九隻，沒討伐過的暗色）；terminal 改成一行文字。存檔 schema 4 起記錄每隻魔物的討伐數，舊存檔的討伐全部算冰呪龍（v0.10 合併後 schema 5）。
- 連動：主回合開始時出營或續打；回合完成或被中斷時，一律鏡像跑離並回營（HP 補滿、進度保存），沒有暫停；子代理的回合忽略。`working_elapsed` 只計主回合，含工具時間。
- 結束規則：冰呪龍有隱藏血量，跨回合、跨 session 累積（`$.store`，全域只有一位獵人），歸零時播 V25 倒地完成討伐，若 Claude 仍在工作，回營後自動開新一場。獵人力竭時播 C17 回營，冰呪龍的血量保留。
- 戰鬥：本機規則加權重的隨機狀態機（`hooks/engine.ts`），數值在 `hooks/data.ts`。冰呪龍血量由固定種子的模擬，依大劍自動校正到 `targetMinutes`（目前 5 分鐘）；太刀與弓的傷害再各乘一個由模擬校正的倍率，三把武器的狩獵時間相近。冰呪龍各 40 場模擬：大劍平均 5.4 分鐘、23% 力竭；太刀 5.5 分鐘、8%；弓 4.9 分鐘、0%。九隻魔物 × 三把武器的時間都在各自目標的 ±15% 內（`combat.test.ts` 會印出），迅龍的力竭率偏高（67–92%），其他大多 0–17%。
- 武器（v0.4）：回合一結束，pane 下方就有「大劍／太刀／弓／隨機」按鈕，獵人還在跑回營地時也能按。選定的武器立刻換上；回合進行中按鈕換成文字、不能換。畫面左下角的「武器 ○○」只是顯示，點了沒有作用。「隨機」在每開一場新狩獵時抽一把，續打同一場時不換。太刀：縱斬連段、袈裟斬，硬直或倒地時用氣刃大迴旋斬。弓：通常射擊、快速射擊，硬直或倒地時用剛射，能從遠處出手。
- 營地（v0.3）：回合之間獵人會走到營火旁烤肉、吃肉；回合開始立刻出營。
- 碰撞（v0.2）：只有攻擊框在有效姿勢碰到受擊框才扣血，同招對同目標只算一次；獵人會跑近、往後翻滾，冰呪龍只用碰得到的招。框在 `hooks/collision-data.ts`；pane 已沒有除錯開關，要看框請用 `huntSvg(phase, view, clock, true)`（測試或 `tools/demo_frames.mts`）。

## 版號

目前版本為 `0.11.1`，顯示於武器選擇區下方。發版時同步更新 `.claude-plugin/plugin.json` 的 `version` 與 `hooks/version.ts`（hooks 執行環境不允許匯入 JSON）。

## 指令

- `/pixel-hunter`：開啟 pane。
- `/hunt-demo`：不經 Claude 回合，手動切換狩獵或撤退（除錯用）。
- `/hunt-demo <魔物 id>`（例 `/hunt-demo great_jagras`）：丟棄進行中的狩獵，立刻出營打一場指定魔物（除錯用；討伐與力竭次數保留）。
- pane 只有遊戲畫面與武器按鈕，沒有除錯開關或除錯文字。

## 素材管線

`tools/extract_sprites.py` 依 `tools/extract_spec.json` 從參考包擷取：

- 動作板以原圖 1:1 擷取。處理只有：從裁切邊緣灌填去背、去除封閉的底色區塊、切除地面線、把各格平移對齊 F1（不改像素）、同群組共用調色盤量化。大劍板與太刀板放大 1.25 倍，對齊 01／02 板的身高；弓板 1:1。太刀板每格都畫了冰呪龍，靠每格的右邊界與 `blank` 區塊排除，被切到的刀光就停在冰呪龍的輪廓前。
- 場景縮成 128×72、16 色，顯示時放大 3 倍。
- 輸出到 `hooks/gen/*.ts`，每列以 RLE 儲存（引擎讀取單檔的上限是 1 MB）。

```bash
PYTHONUTF8=1 python -I tools/extract_sprites.py <hunt_8bit_reference 資料夾>
```

新增魔物來自另一個參考包（`pixel-hunter-all-monsters-reference-v1.1`），用 `--only <group>` 只重擷取該群組（不動其他群組與場景），例如 `--only jagras`、`--only ls`。

`--sheet <png>` 輸出擷取總覽圖，`--measure` 只量測尺寸。

## 已知限制與 v2 項目

- 特效沒有分層：吐息、刀光、冰屑保留在角色影格裡。命中只依資料裡的 `active` 姿勢判定，不從發光像素推定。分層列為 v2。
- 每組動作只有 F1–F4 四個關鍵姿勢，沒有補中間影格，也沒有逐幀校正持武器的手。
- 拿太刀或弓時，待機、營地走路、出營與撤退的跑步都換成持武器步移（L01／B01），閃避換成面向冰呪龍往後滑（太刀 L06 看破斬的後撤段、弓 B07 蓄力步伐），所以跑起來像快步走。受擊、倒地（C15／C17）仍是共通動作，畫面上看不到武器。
- 參考板之間的比例不一致：獵人和冰呪龍的相對大小沿用各板原樣，冰呪龍維持 1:1。
- 未實作：其他太刀與弓的招式、V29 死亡動作、S01 的使用。

## CLI 終端機

終端機預設用 **字元格（`Raster`）** 畫狩獵畫面：每個字元用四分之一方塊（▘▝▀▖▌▞▛▗▚▐▜▄▙▟█）畫 2×2 個像素，角色外圍加一圈深色輪廓，任何支援真彩色的終端機都看得到（含 Windows Terminal）。為了在幾十欄內保持清楚：鏡頭顯示整個場景；每個像素取範圍內**最常出現的顏色**而不是平均（不混色、邊緣乾淨）；角色或特效蓋到四分之一就用角色的顏色；背景壓暗 40% 讓角色跳出來。pane 越寬越清楚：49 欄約 14 列，80 欄約 23 列。圖下方是文字列：狀態與魔物、HP／ST 數字、動作標籤、一行討伐統計。

支援圖片協定的終端機（kitty、Ghostty、iTerm2、WezTerm、foot）可以按 pane 上的「畫面：字元（點此改圖片）」按鈕改成 `Image`（原尺寸 384×216 RGBA，細節完整）；選擇會存起來。程式沒辦法偵測終端機有沒有圖片支援，所以預設是字元；在不支援的終端機（例如 Windows Terminal）選了圖片只會看到 alt 文字「8-bit hunt: 狀態 — 魔物名」，再按一次按鈕即可換回。

`hooks/raster.ts` 直接把場景、角色、營火與特效畫成 RGBA（不經過 SVG；放置、營火、特效與 HP／ST 條與 SVG 版共用 `hooks/shapes.ts`）。每次重畫約 1–3 ms。**限制（未驗證）：** 真實終端機上的字元版畫面是從截圖推斷的版面，我只在使用者的 Windows Terminal 上看過「圖片模式只剩文字」，字元版與圖片版都還沒在真實終端機實測；字元版的色彩上限（引擎每幀約 1024 組前景／背景色對）可能讓部分顏色被近似。

### 讓 pane 變寬（字元畫面更清楚）

字元畫面的清晰度只取決於 pane 有多少欄：49 欄約 98×28 像素，120 欄約 240×68 像素。畫面會用滿 pane 的寬度，但高度不會超過 pane 可用的列數（保留 8 列給下方文字（含版號））；列數不夠時，會照 384:216 的比例縮窄寬度。

- **改用主畫面版面（最有效）**：Claude Code 的全螢幕版面會把 pane 停靠在對話旁邊（終端機 110 欄以上時），寬度只有一部分。主畫面版面則把 pane 放在輸入框上方、用滿終端機寬度。啟動前設定環境變數：

  PowerShell：

  ```powershell
  $env:CLAUDE_CODE_NO_FLICKER = '0'; claude --plugin-dir <mod 資料夾>
  ```

  bash：

  ```bash
  CLAUDE_CODE_NO_FLICKER=0 claude --plugin-dir <mod 資料夾>
  ```

- **終端機視窗放大、字型縮小**：同樣的視窗能塞更多欄與列（Windows Terminal 用 Ctrl+減號縮小字型）。
- **列數也要夠**：寬 pane 若太矮，畫面會被列數限制而縮窄。主畫面版面下 pane 的高度由 Claude Code 決定。

以上依 API 文件說明的版面行為整理，主畫面版面在 Windows Terminal 上的實際寬高尚未實測。

## 多個 session

每個 Claude session 各自推進自己的一份狩獵（`$.state`），但共用同一個 `$.store` 存檔：每 10 秒與每次模式切換時整份覆寫，最後寫入者為準。同時開多個 session 的話，魔物血量會在兩邊的進度之間跳動，討伐統計（`slain`、`slainBy`）可能少算或重複。**建議只在一個 session 開 hunt pane。**
